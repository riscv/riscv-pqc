
[[zvknhk,zvknhk]]
== "Zvknhk" Extension for Vector Keccak

This chapter describes the `Zvknhk` Vector Cryptography extension, which adds
an instruction for the Keccak permutation used by NIST SHA-3 and numerous
post-quantum cryptography (PQC) algorithms.


[[zvknhk-overview]]
=== Extension Overview

This section introduces `Zvknhk`.

`Zvknhk` depends on `Zve64x` and requires `VLEN` to be at least 128 bits
(`Zvl128b`).

As the instructions defined in this specification might be used to implement
cryptographic primitives, they must satisfy the data-independent execution
latency requirements defined for `Zvkt`, the Vector Data-Independent
Execution Latency subset of the RISC-V Vector Cryptography extensions.

[NOTE]
====
The DIEL mandate is independent of support for `Zvkt`: `Zvknhk` defines
instructions used primarily for cryptography, and they would be of little use
if their execution latency could leak information about input data.
====

`Zvknhk` defines `vkeccak.vi` to enable efficient implementations of
Keccak-based sponge functions.

The instructions defined in this specification share the following constraints:

- element group size (`EGS`) is 32 and element group width (`EGW`) is 2048 bits;
- each element is a 64-bit word and the instructions are only defined for
  `SEW=64`;
- `vl` and `vstart` must be multiples of `EGS=32`, otherwise the behavior is
  _reserved_; and
- execution timing is data independent.

Except at `VLEN=128`, as specified in <<zvknhk-vlen128>>, `vkeccak.vi` follows
the ordinary element-group rules described next.

[[zvknhk-element-groups]]
==== Element Groups

`vkeccak.vi` operates on a _vector of element groups_, following the element
group rules of the RISC-V Vector Cryptography extensions. Each element group is
`EGW=2048` bits wide and holds `EGS=32` 64-bit elements. As for every
element-group instruction, `vl` selects `vl/EGS` element groups, and the
instruction processes those from `vstart/EGS` through `vl/EGS - 1`, so that
after a restart only the remaining element groups are processed. `vl` must be
set to the number of `SEW=64` elements to be processed and therefore must be a
multiple of `EGS=32`; likewise `vstart` must be a multiple of `EGS=32`.
Otherwise the behavior is _reserved_. `EGS=32` counts toward `EGSMAX` for the
constraints on setting `vl`, as for any other element-group instruction.

The `vd` operand is an ordinary vector register group of `LMUL` registers
(`EMUL=LMUL`), and `vd` must be aligned to `LMUL` as for any vector
instruction. As for the other element-group instructions, `LMUL*VLEN` must be
at least as large as `EGW`, otherwise an illegal-instruction exception is
raised, even if `vl=0`. At `VLEN=256` this requires `LMUL=8`, and the register
group then holds exactly one element group. At larger `VLEN` a register group
can hold several element groups, and a single `vkeccak.vi` permutes each
active element group independently, so that the same code can process, per
instruction, as many Keccak states as the implementation's vector length
allows. `VLEN=128`, where no
register group of `LMUL<=8` can hold an element group, is covered by the
instruction-specific exception in <<zvknhk-vlen128>>.

.Element groups per `VLEN`. The last column assumes `LMUL=8`, `vl=VLMAX` and `vstart=0`.
[%autowidth]
[%header,cols="^1,^2,^2,^2"]
|===
| `VLEN` | Registers per element group | Minimum `LMUL` | Maximum element groups per instruction

| 128  | 16 (fixed, see <<zvknhk-vlen128>>) | - | 1
| 256  | 8   | 8   | 1
| 512  | 4   | 4   | 2
| 1024 | 2   | 2   | 4
| 2048 | 1   | 1   | 8
| 4096 | 1/2 | 1 (1/2 where `e64,mf2` is supported) | 16
|===

Element group `i` consists of elements `32i` through `32i+31` of the `vd`
register group, laid out according to the standard vector element layout:
element `e` of the register group is held in element position `e mod (VLEN/64)`
of register `vd + floor(e/(VLEN/64))`. At `VLEN=128`, for example, each
register contains two words and element `e` is held in `v[vd + floor(e/2)]`; at
`VLEN=512` and `LMUL=8`, element group 0 occupies `vd` through `vd+3` and
element group 1 occupies `vd+4` through `vd+7`.

Within each element group the 25 active state words (`A[x,y]` = element
`x + 5y` of the group, for `x,y` in `0..4`) are laid out in element order. Bit
`z` of that element is `A[x,y,z]`, with bit 0 the least-significant bit.
Elements 25 through 31 of each element group form the _state tail_ and remain
bit-for-bit unchanged by the instruction. The state tail is an
instruction-defined part of each element group within the body of the vector;
it is not the architectural vector tail determined by `vl`, and `vta` does not
affect it. For example, at `VLEN=256` each register holds four 64-bit words and
the element group in a register group starting at `vd=v0` is laid out as:

.Keccak state layout for `VLEN=256`, `vd=v0` (four 64-bit elements per register)
[%autowidth]
[%header,cols="^2,^3,^3,^3,^3"]
|===
| Register | register element 0 | register element 1 | register element 2 | register element 3

| `v0` | `A[0,0]` | `A[1,0]` | `A[2,0]` | `A[3,0]`
| `v1` | `A[4,0]` | `A[0,1]` | `A[1,1]` | `A[2,1]`
| `v2` | `A[3,1]` | `A[4,1]` | `A[0,2]` | `A[1,2]`
| `v3` | `A[2,2]` | `A[3,2]` | `A[4,2]` | `A[0,3]`
| `v4` | `A[1,3]` | `A[2,3]` | `A[3,3]` | `A[4,3]`
| `v5` | `A[0,4]` | `A[1,4]` | `A[2,4]` | `A[3,4]`
| `v6` | `A[4,4]` | _state tail_ | _state tail_ | _state tail_
| `v7` | _state tail_ | _state tail_ | _state tail_ | _state tail_
|===

Elements of the `vd` register group at or past `vl` are tail elements and
follow the tail policy (`vta`) as for any vector instruction; elements before
`vstart` are unchanged. Because `vl` and `vstart` are multiples of `EGS`, the
body of the vector always consists of whole element groups. As for any vector
instruction, if `vstart >= vl` (including `vl=0`) no element groups are
processed and no destination elements are updated, not even the architectural
tail elements. Masking is not supported: `vm=0` is reserved.

As for every element-group instruction, the permutation is restartable only at
element-group boundaries: `vstart` must be a multiple of `EGS`, execution
resumes with element group `vstart/EGS`, and successful completion resets
`vstart` to zero. An implementation that suspends `vkeccak.vi` must leave
`vstart` at an element-group boundary, so that a trap never exposes an element
group with only some of its state elements updated.

[[zvknhk-vlen128]]
==== Implementations with `VLEN=128`

At `VLEN=128` no register group of `LMUL<=8` can hold a 2048-bit element group:
the largest register group, `LMUL=8`, is 1024 bits wide and `VLMAX` is 16
elements, smaller than `EGS`. So that `Zvknhk` remains implementable at the
minimum `VLEN` of the application-processor profiles, the following
instruction-specific exception applies when, and only when, `VLEN=128`:

- `vkeccak.vi` operates on exactly one element group, held in the sixteen
  consecutive registers `vd` through `vd+15` (`EMUL=16`), independent of
  `LMUL`. This is an exception to the general `EMUL<=8` limit, to the
  requirement `LMUL*VLEN>=EGW`, and to the rule that `EGS<=VLMAX`; none of
  these exceptions apply at any other `VLEN` or to any other instruction.
- `vd` must be aligned to a 16-register boundary, i.e., `v0` or `v16`; other
  values of `vd` are reserved.
- `vl` is not consulted: the instruction behaves as if `vl=32`, including when
  `vl=0`, and the requirement that `vl` be a multiple of `EGS` does not apply.
  Because this fixed group is not strip-mined and does not constrain `vl`, its
  `EGS` is not included when determining `EGSMAX` for the constraints on
  setting `vl`.
- The permutation is not restartable: executing `vkeccak.vi` with a nonzero
  `vstart` raises an illegal-instruction exception. Successful completion
  resets `vstart` to zero, and the fixed-group update is atomic with respect
  to traps.
- Element `e` of the group is held in element position `e mod 2` of register
  `vd + floor(e/2)`, exactly as the standard layout gives for `VLEN=128`.
  Elements 25 through 31 are the state tail and remain unchanged, and all
  registers outside `vd` through `vd+15` are unchanged.

[[insns-vkeccak-vi, Vector Multi-Round Keccak]]
=== vkeccak.vi

Synopsis::
Vector-Immediate Multi-Round Keccak

Mnemonic::
vkeccak.vi vd, imm5


Encoding (Vector-Immediate)::
[wavedrom, , svg]
....
{reg:[
{bits: 7, name: 'OP-VE'},
{bits: 5, name: 'vd'},
{bits: 3, name: 'OPMVV'},
{bits: 5, name: '10010'},
{bits: 5, name: 'imm5'},
{bits: 1, name: '1'},
{bits: 6, name: '101001'},
]}
....

Reserved Encodings::
* `SEW` is any value other than 64
* `imm5` is any value other than `0b00000` (24 rounds) or `0b00001` (12 rounds)
* `vl` or `vstart` is not a multiple of `EGS=32` (at `VLEN=128` `vl` is not
  consulted, and a nonzero `vstart` raises an illegal-instruction exception,
  see <<zvknhk-vlen128>>)
* `vd` is not aligned to `LMUL` (at `VLEN=128`: `vd` is not `v0` or `v16`)
* `vm=0`

Arguments::

[%autowidth]
[%header,cols="4,2,2,2,2,2"]
|===
|Register
|Direction
|EGW
|EGS
|SEW
|Definition

| `vd`   | input  | 2048  | 32 | 64 | Keccak states, one per element group, and state tails
| `imm5` | input  | -     | -  | - | Round-count selector (see Description)
| `vd`   | output | 2048  | 32 | 64 | Permuted Keccak states and unchanged state tails
|===

Description::

Except at `VLEN=128`, as specified in <<zvknhk-vlen128>>, the instruction
applies the Keccak-_p_[1600] permutation independently to each element group
`vstart/EGS` through `vl/EGS - 1` of the `vd` register group.
Within each element group the 1600-bit Keccak state is held in elements 0
through 24, and the result is written back to those same elements. Elements 25
through 31 are not read by the permutation and remain unchanged. Every element
group is permuted with the same number of rounds, selected by the 5-bit
immediate `imm5`:

[%autowidth]
[%header,cols="^2,^2,5"]
|===
| `imm5` | Rounds | Permutation

| `0b00000` | 24 | Keccak-_p_[1600,24] = Keccak-_f_[1600] (SHA-3, SHAKE)
| `0b00001` | 12 | Keccak-_p_[1600,12] (TurboSHAKE, KangarooTwelve)
|===

All other values of `imm5` (`0b00010` through `0b11111`) are _reserved_.

The round constants and their indexing follow FIPS 202 (Sec. 3.2.5 and 3.3)
cite:[NIST:FIPS202]: the
24-round permutation uses round constants `RC[0]` through `RC[23]`, while the
reduced 12-round permutation uses the last twelve, `RC[12]` through `RC[23]`.
This is the same selection as Keccak-_p_[1600,12] used by TurboSHAKE
as specified in RFC 9861 cite:[IETF:RFC9861], which tabulates these twelve
constants re-indexed `0` through `11`.

An illegal-instruction exception is raised if `LMUL*VLEN < EGW`, even when
`vl=0`, except at `VLEN=128`, where the exception of <<zvknhk-vlen128>>
applies instead.


Operation::

The operator `x <<< n` rotates the 64-bit word `x` left by `n` bit positions.
`get_fixed_eg(vd)` and `set_fixed_eg_elem(vd, i, value)` are model primitives
that read a fixed register group and write one element of it.

====
The Sail listing below is *outdated and non-normative*. It still implements
the previous definition, in which `vd` was a single fixed element group
independent of `vl` and `LMUL`; where the listing and this chapter disagree,

====
