== Building the Document

=== Directory Structure

The following directories are used to organize the contents of this repo:

* `dependencies/`: software dependencies needed to build the specification
* `docs-resources/`: resources for all specifications sourced from link:.gitmodules[git submodule]
* `modules/ROOT/`: the specification content, laid out as an
  https://antora.org[Antora] component (`pages/` holds the chapters,
  `resources/` the bibliography); it is the single source for both the PDF and
  the web site
* `src/riscv-pqc.adoc`: the PDF assembler, which includes the chapters from
  `modules/ROOT/pages/`
* `scripts/`: release and site tooling from the RISC-V
  https://github.com/riscv/docs-spec-template[docs-spec-template]
* `build/`: default directory where the build artifacts are generated
* `zvknhk/`: reference implementations and tests for the `Zvknhk` Vector Keccak
  extension — see link:zvknhk/README.md[zvknhk/README.md]. The document includes
  `zvknhk/sail/zvknhk_insts.sail` directly (through the symbolic link
  `modules/ROOT/examples/zvknhk_insts.sail`); building it does not require the
  Sail compiler or the reference-implementation submodules.

=== Prerequisites

To build the document, you'll need the following tools installed on your system:

* Make
* asciiDoctor-pdf, asciidoctor-bibtex, asciidoctor-diagram, asciidoctor-lists, and asciidoctor-mathematical
* Docker

=== Cloning the Repository

```shell
git clone --recurse-submodules https://github.com/riscv/riscv-pqc.git
```

=== Building the Documentation

To start the build process, run:

```shell
cd ./riscv-pqc && make build
```

The link:Makefile[] script will check the availability of Docker on your system:

* If Docker is available, the documentation will be built inside a Docker container using the image `riscvintl/riscv-docs-base-container-image:latest`. This ensures a consistent build environment across different systems.
* If Docker is not available, the documentation will be built directly on your system using the installed tools.

The PDF is named `build/riscv-pqc-v<version>-<YYYYMMDD>.pdf`, as the RISC-V
Architecture Review Committee requires (see link:ARC_SUBMISSION.md[]). The
version and the document state on the title page come from the `v*` git tags
through `scripts/release-info.sh`; an untagged build is labeled as a
development build. To build a specific version, run for example
`make VERSION=v0.8`.

=== Web Site

The same content is published as an Antora site on GitHub Pages at
https://riscv.github.io/riscv-pqc/ by the `publish-site.yml` workflow. To
preview it locally (needs Node.js, and Docker for the diagram server):

```shell
npm install
docker compose up -d kroki
npm run preview         # writes build/site/
docker compose down
```

See link:ANTORA.md[] for how the PDF and the site are built from one source.

=== Releases

Releases are `v*` tags. The milestone versions are `v0.6`, `v0.8`, `v0.9`,
`v0.99` and `v1.0`; see link:ARC_SUBMISSION.md[] and link:SPEC_STATE.md[]. A
pushed tag builds the PDF, attaches it to a GitHub Release, and publishes the
site under `/pqc/<version>/`.

=== Cleaning up

To clean up the generated files, run:

```shell
make clean
```


== Enabling pre-commit checks locally
The repository has some basic commit checks set up with https://pre-commit.com/[pre-commit] that will be enforced by the GitHub CI.
To ensure these checks are also run in the local repository while making changes the following command can be run:
[source,shell]
----
pip3 install pre-commit && pre-commit install
----

When enabling additional checks https://pre-commit.com/#plugins[by editing .pre-commit-config.yaml], it is recommended to run to newly added check on all files in the repository. This can be done with the following command:
[source,shell]
----
pre-commit run --all-files
----
